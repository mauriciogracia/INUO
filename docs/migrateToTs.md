## Phase 1 — devWatcher

**Moved to:** `src/scripts/devWatcher.ts`  
**Compiled output:** `dist/scripts/devWatcher.js`

### Type additions

- `appProcess: ChildProcess | null`
- `debounceTimer: ReturnType<typeof setTimeout> | null`
- `getSystemVersion(): string`, `startApp(): void`, `triggerRebuild(): void`, `watchDirectory(dir: string): void`
- `code: number | null` in `close` event callbacks
- `err: unknown` cast to `Error` in watch catch block

### Path correction

`__dirname` at runtime is `dist/scripts/` → root requires `path.join(__dirname, '../..')`.  
JS version used `path.join(__dirname, '..')` because source lived in `scripts/`.

### package.json changes

```
"dev":   "tsc && node dist/scripts/devWatcher.js"
"serve": "tsc && node dist/scripts/devWatcher.js"
```

### Cleanup

Delete `scripts/devWatcher.js` after confirming `npm run dev` works end-to-end.

## Phase 2 — asciiWebClient

**Moved to:** `src/cli/asciiWebClient.ts`  
**Compiled output:** `dist/cli/asciiWebClient.js`

### Type additions

- `import * as blessed from 'blessed'` — `@types/blessed` already in devDependencies
- `SsePayload` interface `{ channel: string; content: string }`
- `cursor.artificial` replaces `cursor.synthetic` (correct `@types/blessed` property name)

## Phase 3 — Browser app.ts

**Moved to:** `browser/app.ts` (top-level directory, isolated from Node `src/`)  
**Compiled output:** `public/app.js` (overwritten on each build)

### Why a separate directory (not `src/browser/`)

The main `tsconfig.json` targets Node/CommonJS with no DOM lib. Browser code in `src/`
would be included in that compilation and fail without DOM types. Keeping it in `browser/`
keeps the two compilation pipelines completely separate with no tsconfig exclusion rules needed.

### tsconfig.browser.json

```json
{
  "compilerOptions": {
    "target": "ES2020",
    "lib": ["ES2020", "DOM", "DOM.Iterable"],
    "module": "ESNext",
    "outDir": "./public",
    "rootDir": "./browser",
    "strict": true,
    "skipLibCheck": true
  },
  "include": ["browser/**/*"]
}
```

`app.ts` has no `import`/`export` — TypeScript treats it as a script, not a module.
Output has no module boilerplate and loads as a plain `<script src="app.js">`.

### Type additions

- All DOM element queries cast with `as HTML*Element`
- `StatusResponse { version, mode, lang, succinct, debugLevel }` interface
- `SsePayload { channel, content }` interface
- Explicit return types: `filterLogs(): void`, `appendLog(channel, content): void`, `fetchStatus(): Promise<void>`
- `(err as Error).message` in catch blocks (strict `unknown` catch)
- `String(count)` for badge `textContent` assignments (number → string)

### package.json changes

```
"build": "tsc && tsc --project tsconfig.browser.json"
```

### .gitignore addition

`public/app.js` is now a generated artifact — add it to `.gitignore`.

### Cleanup

Once `public/app.js` is regenerated by the build, the original hand-written JS is no longer
the source of truth. The TS file in `browser/app.ts` is the new source.
